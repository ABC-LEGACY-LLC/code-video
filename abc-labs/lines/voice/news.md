  Two techniques of a realtime voice session on a thin client, read in Bluey (Riley Brown, 2026-10-02; repo rbrown101010/bluey-by-riley at 5aab7ff, NO licence: inspiration only, nothing of its code or prompts copied). (2) Key custody: the machine with the key mints a short client secret (POST /v1/realtime/client_secrets, 10-7200 s) with the session bound in it, the device with the mic holds only the secret, the tools run where the hands are (f0331, corrected). The correction (f0512): the secret keeps the key and nothing more — its bound config 'can also be overridden by the client connection' [s7 page.txt:445-447] and one secret opens several sessions until it expires — so whatever must hold (tools, confirmations) is enforced on the server side, and the minting endpoint answers only an authenticated caller. Voice's because it is how a live speech session takes turns and keeps its credential; code-video has no live voice agent today, so this is the line's knowledge, not a page for it.
